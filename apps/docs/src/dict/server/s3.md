# S3 Nesne Depolama Standardı (Object Storage)

* **Standardı Oluşturan:** Amazon Web Services (AWS Simple Storage Service)
* **Resmi Dokümantasyon:** [https://amazon.com](https://amazon.com)

::: info CONCEPT MATRICES
* **Storage Paradigm:** Flat Key-Value Object Storage (Non-hierarchical)
* **Transport Protocol:** RESTful HTTP/HTTPS API (XML / JSON payloads)
* **Authentication Mechanism:** AWS Signature Version 4 (HMAC-SHA256) & STS Temporary Credentials
* **Addressing Styles:** Virtual-Hosted-Style (`bucket.s3.<domain>`) & Path-Style (`s3.<domain>/bucket`)
* **pr2cloud Implementation:** Self-Hosted MinIO / Silo (`https://s3.<domain>`)
:::

## Resmi Tanım
**S3 (Simple Storage Service)**, verileri klasik işletim sistemi klasörleri (POSIX dosya sistemi) yerine düz (flat) bir adres uzayında **Nesne (Object)** olarak saklayan ve **RESTful HTTP/HTTPS API** üzerinden erişim sunan endüstri standardı nesne depolama protokolüdür. `pr2cloud` ekosisteminde tüm uygulamalar, statik varlıklar ve kullanıcı dosyaları sunucu diskinden bağımsız olarak S3 protokolü üzerinden yönetilir; bu sayede depolama motoru (MinIO, Silo, Garage, Cloudflare R2 vb.) değişse dahi uygulama kodunda hiçbir değişiklik gerekmez.

## Sözlük Veritabanı (Lexical Database)

| Terim | Açıklama |
| :--- | :--- |
| **Bucket (Kova)** | Nesnelerin gruplandığı en üst düzey mantıksal konteyner. Erişim politikaları ve yaşam döngüsü kuralları kova bazında tanımlanır. |
| **Object (Nesne)** | Depolanan temel veri birimi; dosyanın ikili içeriği (binary payload), benzersiz anahtarı (`Key`) ve üst verilerinden (`Metadata`) oluşur. |
| **Object Key (Anahtar)** | Kova içindeki bir nesneyi benzersiz şekilde tanımlayan tam yol adı (Örn: `tenant-42/invoices/2026-11.pdf`). |
| **Prefix (Ön Ek)** | S3 düz mimarisinde gerçek klasörler olmadığı için `/` ayıracıyla klasör hiyerarşisini simüle eden ve çoklu kiracı (multi-tenant) izolasyonu sağlayan anahtar başlangıcı. |
| **Presigned URL** | Gizli API anahtarlarını istemciye (tarayıcıya) açmadan, kullanıcının doğrudan S3 sunucusuna zaman sınırlı yükleme (`PUT`) veya indirme (`GET`) yapmasını sağlayan kriptografik imzalı bağlantı. |
| **Multipart Upload** | Büyük boyutlu dosyaların (video, yedek arşivi vb.) parçalara bölünerek paralel ve kesintiye dayanıklı biçimde yüklenmesi mekanizması. |

## Cheatsheet: Klasik Dosya Sistemi vs. S3 Standardı

| Özellik | Klasik Dosya Sistemi (POSIX / Disk) | S3 Nesne Depolama Standardı |
| :--- | :--- | :--- |
| **Veri Yapısı** | İç içe fiziksel klasörler (`/uploads/user1/...`) | Düz (Flat) Kova + Anahtar (`tenant-1/...`) |
| **Erişim Yöntemi** | İşletim sistemi dosya yolu (`fs.readFile`) | HTTP/HTTPS REST API (`GET / PUT / DELETE`) |
| **Ölçeklenebilirlik** | Tek sunucu diski ve inode limitiyle sınırlı | Sunucu ve konteynerden bağımsız, yatay ölçeklenebilir |
| **Güvenli Paylaşım** | Backend üzerinden dosya akışı (Proxy) gerekir | **Presigned URL** ile doğrudan istemci-S3 transferi |
| **Hesap Kapatma / Temizlik** | Fiziksel klasör ve izin temizliği gerektirir | İlgili `Prefix` altındaki tüm nesnelerin API ile toplu silinmesi |

## pr2cloud Mimari Kuralları (S3 Kullanım)
1. **Path-Style Erişim Zorunluluğu:** Self-hosted ortamlarda alt alan adı sertifika karmaşasını önlemek için SDK istemcilerinde `forcePathStyle: true` (`https://s3.<domain>/<bucket>/<key>`) standardı kullanılır.
2. **Fiziksel Klasör Yasağı:** Hiçbir uygulama konteyneri kullanıcı yüklemelerini kendi yerel diskine veya kalıcı volume içine kaydetmez; tüm medya ve belgeler S3 API üzerinden aktarılır.
3. **Kiracı İzolasyonu ve Yaşam Döngüsü:** Kullanıcı dosyaları `saas-users/tenant-{id}/` ön ekiyle izole edilir; kullanıcı hesabı kapatıldığında ilgili ön ek altındaki tüm nesneler kalıcı olarak silinir.
